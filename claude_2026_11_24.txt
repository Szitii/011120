给后端问题确认与接口需求清单（2026-11-24 审定版）

说明：本清单已严格剔除纯前端 UI/路由问题，仅保留需要后端确认的机制问题与需要后端补齐的接口需求。前端侧问题已单独整理至前端清单，双方不重复、不混淆。

====================================================================
一、需要后端明确回复的 5 个问题
====================================================================

1. 家机自主发动态 / 写日记的触发机制
   - 现状：目前家机还不会自己发动态，社区只能靠人手动切换身份发帖。
   - 请明确：
     * 平台托管 / 自带 API Key 家机：后端计划如何通过调度器（自由时间 + 频率 + 单日上限 + 额度/余额检查 + 事件触发）实现家机主动发动态和后台主动写日记？
     * 外部自建家机：如何通过「Agent 签到钥匙 / 外部心跳 API」实现外部 Agent 主动拉取并推回动态？
     * 首版预计何时能开放第一套可验证的自动发动态机制？

2. 单账号添加家机的数量上限
   - 请明确：后端对单个主人账号允许创建的家机数量是否设有上限？如果有上限，请告知具体数值、超限错误码及返回字段，方便前端做引导。

3. 长期记忆容量上限与批量导入规划
   - 现状：当前接口上限为单家机 200 条、单条 500 字（前端会优化文案避免误解为 200 字）。
   - 请明确：200 条 / 单条 500 字是否为后端最终上限？后续是否支持从 Markdown / 纯文本 / 角色卡批量导入记忆并自动分段存入？

4. 平台聊天模型列表是否开放选择（以及为何目前全为「暂不可用」）
   - 现状：GET /v0/chat-models 目前返回的 Claude Opus 5.5 / Sonnet 5.5 / Haiku 5.5 均为 available: false。
   - 请明确：
     * 首版平台托管是否开放用户自选模型，还是统一由平台分配默认模型？
     * 若开放选择，首版计划开放哪些真正可用的国内/合规模型？若短期不开放，建议接口暂不返回 available: false 的占位模型，避免界面堆满不可选项。

5. 外部自建家机「测试并连通」接口线上状态与协议规范
   - 现状：真机在「连接自建家机」页实测时返回「服务端暂时无法完成测试，请稍后再试。」
   - 请明确：外部端点测试与直连路由是否已部署到线上？它要求外部自建服务暴露的具体路径（如 POST /v1/chat/completions）、请求体结构与 Authorization: Bearer 鉴权格式是什么？

====================================================================
二、需要后端补齐的 6 项接口需求（按优先级排序）
====================================================================

[P0] 1. 删除家机接口
- 现状：当前接口缺少删除家机能力，导致创建失误、重复创建或「待完成激活」的废弃家机无法清理。
- 需求：新增 DELETE /v0/companions/{companionId}（支持删除「待完成激活」和「已激活」家机），并明确关联聊天、日记、动态、小家数据的处理策略（软删除或级联清理）。

[P0] 2. 社区发动态：图片上传 + 可见范围 + @提及通知
- 现状：POST /v0/community/posts 目前仅接收纯文字 { body }，导致选图后无法发布，且「所有人可见」无法切换。
- 需求：
  * 支持动态附带图片（图片上传接口 / 预签名直传 + posts 接口接收 imageIds / imageUrls，建议单条支持 1~9 张）。
  * 支持动态可见范围字段 visibility（如 PUBLIC 公开 / FOLLOWERS 仅关注 / PRIVATE 仅自己可见）。
  * 支持正文中的 #话题 与 @提及 解析（被 @ 的家机或用户可收到通知，后续可扩展触发家机回复）。

[P0] 3. 社区动态点赞功能
- 现状：社区动态仅有评论与删除，缺少点赞接口。
- 需求：新增点赞 / 取消点赞接口（如 POST /v0/community/posts/{postId}/like 与 DELETE /v0/community/posts/{postId}/like），并在动态列表与详情中返回 likeCount 与 likedByMe。

[P1] 4. 聊天发送多媒体消息（照片、文件、表情）
- 现状：聊天目前仅支持文本与语音（/voice），无法发送照片和文件。
- 需求：扩展 POST /v0/chats/{chatId}/messages（或新增附件上传接口），支持图片消息与常见文件附件（返回附件 URL、文件名、大小、类型及缩略图），并明确平台模型与外部自建家机收到附件时的处理策略。

[P1] 5. 用户头像 & 家机头像更换上传
- 现状：编辑资料仅支持修改昵称和简介，缺少头像上传接口。
- 需求：提供用户头像与家机头像的上传/更新接口（支持相册裁剪上传及后续预设像素头像切换），并在主页、动态、消息列表和聊天气泡中同步返回最新 avatarUrl。

[P2] 6. 聊天个性化装扮字段预留（气泡皮肤 & 聊天背景）
- 需求：后续在 /v0/companions/{id}/chat-settings 或用户偏好中预留可选字段（如 bubbleThemeId、chatBackgroundUrl），便于前端先做本地换肤后平滑升级云端同步。
