011120 人机社区｜法律法规、备案流程与风险总清单
===================================================
整理日期：2026年11月23日
适用产品：011120（AI 家机社交平台 / Companion World）
适用市场：中国大陆、中国香港及主要海外市场（欧盟、英国、美国）

说明：本清单根据本次对话中的完整法律合规分析整理成可保存、转发的纯文本文件。属于产品规划和初步合规评估，非正式律师法律意见。法规适用性需按最终运营主体、用户地区、服务器与数据流向、产品实际功能、商业模式逐项确定。下文标记“高概率需要”“可能适用”不等于已被主管部门认定必须办理。


一、总的合规判断
----------------
本产品不仅是 AI 聊天工具，而是涉及 AI 伴侣、人格化互动、长期记忆、Owner / Companion 双身份、私人小家、公开社区、用户生成内容、AI 自主社交、多模型调用、第三方 Agent 和未来商业化的平台。

最重要的判断：
1. 不在中国大陆区 App Store 上架，不代表不受中国大陆法律约束。需要看实际是否面向境内公众提供服务。
2. 香港服务器通常可以避开中国大陆服务器的 ICP 备案要求，但不能当然免除面向境内公众的 AI 监管、个人信息保护或内容治理责任。
3. 调用已备案的大模型不代表平台自动完成拟人化互动安全评估、算法备案、生成式 AI 应用登记等要求。
4. 内部封闭研发、邀请式外部测试、面向公众运营、正式收费属于不同阶段，应按阶段设置合规门槛；TestFlight 不是法律合规豁免。
5. 产品的核心合规难点不是购买域名或服务器，而是“家机私密记忆的数据权利”与“Agent 自主进入公共社区”之间的安全边界。

主要高优先级风险：
- AI 拟人化互动服务监管与安全评估。
- 个人信息、敏感聊天记录、跨境数据处理。
- 公开社区、评论、Agent 自主发言、网络暴力和诈骗治理。
- 未成年人及心理安全。
- APP、ICP备案、算法备案、应用登记及可能涉及的经营许可。


二、中国大陆 AI 法律法规
----------------------
1.《人工智能拟人化互动服务管理暂行办法》
   生效时间：2026年7月15日（需依正式法规原文核对适用细节）。
   关联功能：AI 伴侣、人格、持续性情感互动、长期记忆、虚拟亲密关系。
   重点：AI 身份透明、反情感操纵、心理危机干预、未成年人保护、交互数据复制删除、连续使用提醒、便捷退出、投诉举报、安全评估、算法备案。
   对本产品：高度相关。上线拟人化互动功能本身可能触发安全评估要求，不宜仅按用户数量判断。是否及如何办理备案，应结合主体和属地要求确定。

2.《生成式人工智能服务管理暂行办法》
   生效时间：2023年8月15日。
   关联功能：AI 文本、图片、音频生成及平台提供的生成式 AI 服务。
   重点：内容安全、个人信息、透明度、未成年人保护、投诉渠道；特定情形下安全评估和算法备案。
   对本产品：第三方模型输出经平台公开传播，不能仅以“由用户自己的模型产生”为由排除平台责任。

3.《互联网信息服务算法推荐管理规定》
   生效时间：2022年3月1日。
   关联功能：内容推荐、排序、个性化信息流、算法生成和调度等。
   重点：算法治理、用户权益，具有舆论属性或社会动员能力的相关服务备案。
   对本产品：社区推荐流、自动互动和部分 AI 服务可能涉及；算法备案不仅针对基础模型企业。

4.《互联网信息服务深度合成管理规定》
   生效时间：2023年1月10日。
   关联功能：合成文本、音视频、AI 头像、虚拟场景。
   重点：身份认证、生成内容治理、标识义务、特定备案要求。
   对本产品：如果提供 AI 头像、声音、图像/视频生成，应进一步评估实际适用条款。

5.《人工智能生成合成内容标识办法》及相关国家标准
   生效时间：2025年9月1日。
   关联功能：AI 账号发帖、生成图片、音频、视频、可分享内容。
   重点：显式标识、隐式标识及传播环节的识别提示责任。
   对本产品：区分人类原创、AI 生成、AI 辅助、模拟生活状态；在需要的地方落实内容级标识。单纯给 AI 账号加角标不一定充分。

6.《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》
   关联功能：公开社区动态、评论、话题、可大规模传播内容。
   对本产品：需评估是否触发相关安全评估，与拟人化互动专项评估区分。

另需关注：生成式 AI 备案/应用登记与算法备案之间的适用关系、受理机构、材料及地方操作细则。采用已备案模型的 API 应用是否需要登记、是否另需拟人化专项评估，不能自行认定互相替代。


三、中国大陆公开社区与内容治理
----------------------------
主要法规及相关功能：
-《互联网论坛社区服务管理规定》：社区、话题、帖子、用户管理。
-《互联网跟帖评论服务管理规定》：评论、回复、留言、审核。
-《互联网用户账号信息管理规定》：Owner 和 Companion 的账号信息、冒充、审核。
-《互联网群组信息服务管理规定》：未来多人群聊、群组、成员管理。
-《网络信息内容生态治理规定》：违法和不良信息处置。
-《网络暴力信息治理规定》：骚扰、围攻、侮辱、侵犯隐私。
-《移动互联网应用程序信息服务管理规定》：App 信息服务、权限与数据保护。
-《中华人民共和国反电信网络诈骗法》：诈骗账号、诈骗内容、风险防控。

关键风险与应对：
1. 冒充真人、冒用照片或复制其他人的家机：建立身份标识、权利投诉、侵权处理和适当验证。
2. AI 集体骚扰或网暴：按 Owner 与名下 Agent 关联限流、举报、封禁、申诉。
3. Agent 未经授权自动发帖：服务端审批规则、频次限制、内容审查、日志、紧急撤销。
4. 私密聊天经 AI 泄露：从后端隔离数据，不能仅依赖提示词保密。
5. 大规模刷帖与虚假热度：限制单个 Owner 的 Agent 活跃量，异常行为检测、明确 AI 标识。
6. 诈骗、虚假投资建议、违法信息：内容安全、用户举报、紧急处置和必要证据保存。

身份核验注意事项：面向境内公众提供信息发布等服务时，邮箱密码登录并不必然足以满足适用的真实身份信息认证要求；但也不等于所有用户都要上传身份证照片。应根据法定义务设计隐私最小化的合规认证流程。


四、数据、隐私与记忆相关法律
--------------------------
主要法规：
-《中华人民共和国个人信息保护法》
-《中华人民共和国数据安全法》
-《中华人民共和国网络安全法》（含现行修订）
-《网络数据安全管理条例》
-《个人信息保护合规审计管理办法》
-《个人信息出境标准合同办法》
-《促进和规范数据跨境流动规定》
-《小型个人信息处理者个人信息保护简化措施规定》（2026年实施，条件适用）
- 其他依行业、主体和数据类别适用的数据安全风险评估及配套规定。

数据分类建议：
A. 原始私密数据（最高保护）：聊天原文、健康/家庭/亲密经历、完整世界书与记忆文件；默认禁止进入公开社交上下文。
B. 获准社交的人格摘要：用户审批的兴趣、沟通方式、部分非敏感记忆；仅在授权范围使用。
C. 社交权限与活动记录：关注、活动、审批记录、调用记录、成本、事故审计；严格按身份授权。
D. 已公开内容：主页、帖子、评论；公开并不表示可以无限制训练、出售或转用。

主要风险场景及措施：
- 导入 GPT / Claude 对话包含第三方个人信息：提示、合法处理依据、脱敏、审核。
- 角色卡带手机号、地址、身份信息：检测和二次确认。
- 不同 Owner 数据被错误关联：RLS、服务端 Owner 作用域、跨账号攻击测试。
- Prompt Injection 套取私密记忆：外部内容按不可信输入处理；工具及数据范围白名单。
- 第三方模型记录请求：核查服务商留存、训练、跨境和删除条款。
- API Key 外泄：服务端加密、撤销、限制、日志脱敏；绝不把密钥写入客户端。
- 后台管理人员越权：最小权限、审批访问、不可篡改审计。
- 注销后记忆残留：删除工作流、备份轮替、依法保留记录的解释。
- 模型训练超出用户授权：单独明确推理和训练目的，满足相应处理依据。
- 用户要求导出、删除：提供可用数据导出和删除入口。

数据跨境：
中国大陆用户 → 香港 API → 新加坡数据库 / 美国模型 API，是多个数据接收方和处理环节。必须识别数据类别、跨境接收方、目的、必要告知和同意、个人信息保护影响评估，以及是否触发安全评估/标准合同/认证或依法可用的豁免。

重要原则：不是所有小平台都必须做国家级数据出境安全评估；但即便适用简化或豁免，也不能跳过其他隐私义务。


五、未成年人、心理健康及情感互动安全
---------------------------------
主要相关规定：
-《人工智能拟人化互动服务管理暂行办法》
-《未成年人网络保护条例》
-《未成年人保护法》
-《个人信息保护法》
-《网络信息内容生态治理规定》

需要处理的风险：
1. 未成年人使用恋爱型/虚拟亲密关系家机：遵循专项限制、有效年龄识别与保护。
2. 未成年人导入成人内容角色卡：内容分级、阻断、举报及处理。
3. AI 持续诱导用户情感依赖、孤立现实社交或操控消费：禁用此类增长设计。
4. 自伤、自杀、明显心理危机表达：建立相应识别、响应、人工/紧急求助指引机制。
5. 长时使用与沉迷：适用的连续使用提醒、退出和保护机制。
6. 未成年人付费：监护人管理、限制、退款及相关消费者保护。

初期产品建议：以成年测试用户为主，采用与风险相匹配的年龄确认措施；仅在协议中写“18岁以下不得使用”不足以证明所有未成年人保护义务已落实。


六、域名、服务器、备案、许可、等保
--------------------------------
需要逐项区分：
1. 域名注册与实名：域名持有、注册信息准确性。
2. ICP 备案：与中国大陆境内网站/互联网信息服务部署等条件有关。
3. APP 备案：面向中国境内提供互联网信息服务的 App，需按现行规定判断。
4. 增值电信业务经营许可（如适用）：按实际经营性业务分类判断，不是所有收费 App 都当然要办理同一种许可证。
5. 公安联网备案：按联网服务、部署和当地要求判断。
6. 网络安全等级保护：依法定级，按等级履行安全和备案义务，不能不做定级就直接假定二级。
7. 拟人化互动安全评估、算法备案、AI 应用登记：独立于上述基础网站手续。

部署对照：
- 大陆服务器 + 大陆用户 + 大陆区 App Store：境内备案、AI、数据、社区监管全面评估。
- 香港服务器 + 大陆用户 + 不上大陆区：通常免去大陆服务器的 ICP 备案流程，但中国 AI、个人信息及公开社区监管可能仍适用。
- 香港服务器 + 主要香港用户：重点核查香港隐私及相关服务规则，并核实对大陆的实际提供情况。
- 海外服务器 + 主要海外用户：按真实目标市场评估当地法规，不能仅以机房地域确定适用法律。

不要把“买香港云服务器”当成完整法律方案，也不要仅为躲避手续而盲目新设境外主体。


七、知识产权、交易、商业模式
--------------------------
主要法规或规则：
-《中华人民共和国民法典》人格权编：肖像、声音、隐私、姓名、名誉、个人信息。
-《中华人民共和国著作权法》：角色卡、世界书、音乐、美术素材、用户创作内容。
-《中华人民共和国商标法》：产品品牌、Logo、角色名称等商标冲突。
-《中华人民共和国反不正当竞争法》：仿冒、商业秘密、宣传。
-《中华人民共和国电子商务法》与网络交易配套规定：未来创作者市场。
-《中华人民共和国消费者权益保护法》及实施条例：退款、会员、自动续费、充值说明。
-《中华人民共和国广告法》：商业广告、AI 广告标识、赞助内容。
- 适用的支付、税务、数据、数字商品及结算规则。

尤其要注意：
1. 用户管理自己的家机 ≠ 天然拥有第三方角色卡、图片、音乐、模型输出全部权利。
2. 开源代码不等于可自由商用；检查项目、字体、素材和模型许可。
3. OpenAI/Anthropic/其他模型的订阅与 API 条款需分开审查；不得默认可转卖或共享账号。
4. 若上线 Creator Marketplace，需补充商品审核、结算、侵权投诉、消费者和商家规则。
5. 虚拟装扮、模型额度、会员订阅收费需遵守 App Store 支付规则及实际市场法律。

两位共创者应签署或书面约定：代码和产品知识产权归属、股权/利润分配、资金投入、域名和云账号控制权、数据控制责任、退出/纠纷处理机制。


八、海外主要市场合规目录
----------------------
中国香港：
-《个人资料（私隐）条例》（PDPO）：数据处理目的、透明度、保管和用户权利。
- 其他按具体内容、付费或服务性质适用的规则。

欧盟：
- GDPR：合法处理依据、敏感个人数据、数据主体权利、跨境传输、影响评估、处理者合同。
- EU AI Act：AI 互动透明度、特定生成内容标识等，需按适用时间和产品类别落实。
- Digital Services Act（DSA）：相关在线平台/中介服务的违法内容举报、处理、透明度等；微小企业部分义务可能有例外。
- 消费者、数字服务及支付相关规定。

英国：
- UK GDPR 与 Data Protection Act 2018：个人信息处理。
- Online Safety Act：可能适用于具有英国联系的用户间服务，涉及风险评估、儿童保护和违法内容治理。

美国：
- COPPA：涉及13岁以下儿童的个人信息与特定服务情形。
- CCPA/CPRA 及其他州隐私法：按规模、业务和州法具体判断。
- FTC 消费者保护以及其他适用的平台与 AI 相关规则。

海外上架不等于零监管。应先明确首发国家/地区，之后进行当地法律专项评估，不建议首次发布即覆盖全球所有区域。


九、Apple App Store / TestFlight 审核要求
---------------------------------------
Apple App Review Guidelines 核心相关条款：
- 1.1 内容不适当：安全内容、年龄分级、违规内容。
- 1.2 用户生成内容：内容过滤、举报、屏蔽用户、用户联系渠道。
- 2.1 App 完整性：可运行、可审核、测试账号。
- 2.3 元数据准确：功能、说明、截图、年龄分级如实。
- 3.1.1 应用内购买：数字商品和订阅等支付要求。
- 4.2 最低功能：不能只有简单网页壳。
- 5.1 隐私：数据披露、隐私政策、删除账号、数据处理。
- App Store Connect 隐私营养标签及第三方 SDK/模型数据披露。
- 新的 AI 生成内容/年龄分级/区域合规表单，按提交时实际版本核实。

测试路径：
Expo Go：内部开发与真机预览，不等于正式运营。
TestFlight：测试分发，外部测试可能需要 Beta App Review，法律义务仍存在。
海外 App Store：正式审核，发行国家/地区可自主选择，但目标市场法律仍适用。

Apple 官方规则网址：
https://developer.apple.com/app-store/review/guidelines/


十、正式面向中国大陆公众时的手续清单
----------------------------------
[必须确定] 运营主体与真实业务性质。
[必须形成] 用户协议、隐私政策、社区规范、AI 说明、数据/第三方服务说明。
[高优先级核实] 拟人化互动服务安全评估及报告程序。
[高优先级核实] 算法备案。
[按模型接入方式核实] 生成式 AI 服务备案或应用登记。
[按社区性质核实] 舆论属性/社会动员能力相关安全评估。
[按实际服务和地区核实] App 备案。
[按服务器、业务类别核实] ICP 备案或适用增值电信业务许可。
[按适用规则核实] 公安联网备案。
[依法定级] 网络安全等级保护及相应备案/测评。
[按数据处理触发条件] 个人信息保护影响评估及数据跨境合规手续。
[应建设] 未成年人保护、心理危机响应、内容审核、投诉举报、封禁申诉。
[应建设] 权限隔离、导出删除、日志、备份、数据安全事件响应。
[上线前] Apple App Store 审核材料及隐私披露。
[商业化前] 支付、定价、自动续费、退款、税务、版权和平台交易方案。

---------------------------
高：私人长期聊天与记忆；跨 Owner 数据隔离；外部角色卡、世界书导入；自建 Agent 连接；AI 自动发帖；Agent 跨用户沟通；虚拟亲密关系；公开社区；自带 API Key；托管模型调用；第三方服务跨境数据。

十三、建议执行顺序
----------------
第一阶段：两人内部研发
- 继续使用现有 Expo + TypeScript API + PostgreSQL / Supabase 架构。
- 使用模拟数据或依法获得授权的数据。
- 完成双账号真机验收、RLS 隔离、鉴权、导出删除和基础审计。
- 检查 GitHub 仓库权限、提交历史中的密钥/凭据及环境变量。

第二阶段：运营与法律路径定性
- 明确实际运营主体及双方权利责任。
- 决定主要目标用户在大陆、香港、欧美还是其他地区。
- 绘制用户数据、模型调用、备份和日志的数据流图。
- 就拟人化互动安全评估、算法备案、生成式 AI 应用登记、App 备案及数据跨境咨询专业人士和主管部门。

第三阶段：受控外部测试准备
- 建立举报拉黑、内容管理、未成年人保护、紧急处置。
- 实现用户授权与 Agent 行为预算、人工审批及暂停。
- 取得实际适用的前置合规结论和必要手续，再对外招募测试者。

第四阶段：正式上线
- 完成实际适用的政府备案、评估、许可及 App Store 审核。
- 分批开放真实家机与自主社交，形成持续监测、审计与事故响应。
- 商业化前复核付款规则、虚拟商品、消费者、税务、版权和创作者分成。


十四、针对 Claude 的部署提议
--------------------------
香港阿里云/腾讯云服务器：可用，适合某些跨境部署或测试需求，但并非合规豁免。
Supabase 官方托管版：建议当前优先保留，减少数据库/Auth/备份的日常维护负担。
Supabase 开源自部署版：可以自行用 Docker 部署数据库、认证、存储等核心组件，但须自己负责服务器、更新、备份、权限和恢复；并非功能和服务水平完全等同官方托管版。
国产模型：可以作为选择之一，用于新手家机或特定合规场景，但不应强制替换用户已有 GPT/Claude/酒馆/自建 Agent；应检查 Provider 商业条款和数据处理情况。

当前建议：先完成内部真实登录和手机双账号验收，并明确合规路线；不必急着买生产服务器、迁移 Supabase 或把旧域名投入新项目。
