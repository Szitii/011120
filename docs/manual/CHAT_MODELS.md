# 聊天模型:怎么打开、怎么关、怎么调试

## 打开

1. 模型清单在 `backend/config/chat-models.json`(换一个文件:设环境变量 `CHAT_MODELS_FILE`)。
   - `defaultModel`:家机没选模型时用哪个。
   - `decisionModel`:群里"适中"的家机先用它判断要不要开口;填 `null` 就让回复模型自己判断。
   - 每个模型写明厂商、厂商那边的模型名、档位、每百万 token 的价格(美元)、是否启用。
   - 加一家用 OpenAI 通用格式的厂商:在 `providers` 里写 `baseUrl` 和存密钥的环境变量名,再在 `models` 里加模型。
2. 密钥只放环境变量,不进文件、不进数据库,例如 `ANTHROPIC_API_KEY`、`DEEPSEEK_API_KEY`。
   有密钥的厂商,它的模型才可用;一个都没有时:开发服务器用假回复,正式服务器的回复显示"即将推出"。
3. 重启 API 服务器。`GET /v0/chat-models` 会列出每个模型现在能不能用。

## 现在用的(2026-11-25 起)

平台模型用 DeepSeek:`deepseek-flash`(默认,也用来判断群里要不要开口)和 `deepseek-v4-pro`(贵一档)。
都关掉了"思考模式"(DeepSeek 默认开着;聊天用不上,开着更慢,思考的内容也按输出收费)。
清单里的价格按 DeepSeek 官网的高峰价、不按缓存命中算(api-docs.deepseek.com/quick_start/pricing):
flash 输入 $0.30 / 输出 $1.20,v4-pro 输入 $1.32 / 输出 $3.96(每百万 token)。
非高峰时段(UTC 工作日 01–04、06–10 点以外,和周末)DeepSeek 实际只收一半,所以花费页上的数会比账单高,最多高一倍。
密钥放在 API 服务器的 `DEEPSEEK_API_KEY`。

## 备用 Key(同一家厂商的第二把)

一家厂商只有一把 Key 时,这把 Key 一出问题(失效、欠费、被限流,或者厂商那边出错),所有用平台模型的家机都回不了话。所以可以给厂商配第二把:

- 清单里厂商多一项 `backupApiKeyEnv`,写存备用 Key 的环境变量名。DeepSeek 已经写好了:`DEEPSEEK_BACKUP_API_KEY`。没设这个环境变量时,一切和以前一样。
- **什么时候换**:第一把 Key 这一次调用失败,而且换一把可能成功时——被拒绝(401、402 欠费、403)、被限流(429)、厂商出错(5xx)或者连不上。同一条回复马上用备用 Key 再发一次,主人感觉不到。请求本身有问题(400、404)或者已经超时的不换:换一把也是一样的结果。
- 第一把被拒绝(401 / 402 / 403)之后的 5 分钟里,先用备用 Key,不让每条回复都先等一次同样的拒绝;5 分钟后再试第一把,好了就自动换回来。
- **备用 Key 最好来自另一个账号**。同一个账号的两把 Key 余额是同一份,欠费时一起失效;只能防"Key 被删了或泄露了要换"。
- **怎么知道备用 Key 在顶班**:后台"模型与额度"页的"模型厂商"表里,备用 Key 单独一行,各自显示余额。第一把那一行余额不足或查不到,就是备用在用。日志里那条回复的 `chat_reply` 记录会带 `"key":"BACKUP"`(`fly logs -a companion-social-api | grep '"key":"BACKUP"'`)。现在没有主动告警,要自己去看。
- **怎么设**:`bash ~/GE/011120-model-key.sh DEEPSEEK_BACKUP_API_KEY`(弹出输入框,同时存进 API 服务器和后台)。
- 花费记账不变:一条回复只记一次,按实际成功的那次调用结算。花费页不区分是哪把 Key 付的钱。
- 这不是"换一家厂商兜底":DeepSeek 整个不可用时,两把 Key 都没用。那需要在清单里再配一家厂商的模型,目前没有做。

主人自带 Key 的家机不走这里:主人自己的 Key 失败时不会换成平台的 Key(那样会悄悄花平台的额度),而是在失败的那条回复上告诉主人原因(失效、欠费、限流、模型名不对、连不上等),见前端说明第 39 节。日志里那条记录带 `"connection":"NO_BALANCE"` 这样的原因。

## 看图(主人在聊天里发图片)

- 清单里能接收图片的模型标 `"vision": true`(现在只有 `deepseek-flash`;DeepSeek 的文档没有说 `deepseek-v4-pro` 能看图,所以没标)。
  `visionModel` 是专门负责"把图片写成一段描述"的模型,现在也是 `deepseek-flash`;不写就用第一个能看图的。
- **每张图只描述一次**:轮到家机回复时,服务器用主人自己的登录凭证从存储里取图(服务器没有存储密钥),让 `visionModel` 写一段不超过 200 字的描述,存在图片旁边。之后任何回复、任何模型读到的都是这段描述。
- **能看图的模型还会直接拿到原图**:最近 6 条消息里的图(最多 4 张)随这次回复一起发给它,所以刚发的图它是真的在看,追问细节也答得上。再往前的图只剩描述。
- **看不了图的家机**(选了 `deepseek-v4-pro` 的、主人自带 Key 的、接了自己 Agent 的)只读描述。所以主人自带 Key 时,图片也是交给**平台的** DeepSeek 写描述,不发给主人自己的模型。
- 花费:描述一张图是一次单独记账的模型调用,算在那一轮回复所属的家机当天的额度和次数里(一轮里两张新图加一条回复 = 三次调用);一张图最多按 1024 个输入 token 记。主人自带 Key 的家机,这一笔也记在平台额度里。
- 一张图**因为它自己的原因**两次没看成(文件没了、不是图片、模型拒绝描述、厂商说请求不对)就标成"看不到",不再重试,App 会告诉主人。不算在图片头上的情况:平台没有能看图的模型、当天额度用完、厂商或存储临时出错、或者这一轮没有主人的登录凭证(家机主动找主人、到点提醒)。这时图片先放着,家机会说"还没看到",下次主人发消息时再看。
- 上限:每条消息最多 4 张,每张最多 1 MB(jpg / png / webp),每位主人每天 30 张(`companion_private.chat_quota.daily_images`,后台现在没有改它的入口)。
- 回复日志 `chat_reply` 里:`seen` 是这一轮新描述了几张,`shown` 是随回复附上了几张原图。
- 运营看不到聊天里的图片:后台"查看私聊"只显示 `[图片]` 这样的文字,服务器和后台都没有存储密钥。

## 工具(家机查菜单、下外卖单;默认关)

- **是什么**:主人给家机接一个工具服务器(用的是 MCP 协议),填上他自己在对方那里的令牌。家机回复主人时,模型可以先调用工具(查菜单、算价格),拿到结果再回答。会改东西的工具(下单、取消订单)模型调用了也不会执行,而是在聊天里出一张确认卡,主人点确认才执行。
- **总开关**:后台"模型与额度"页的功能开关"家机使用工具"(`COMPANION_TOOLS`),默认关。打开前请先用自己的账号试一遍。
- **目录**:后台"模板与技能"页的"工具服务器"。每个服务器写两栏工具名:可以直接用的、要主人确认的。**两栏都没写的工具,家机用不了**;对方新增工具不会自动生效。线上自带麦当劳(`https://mcp.mcd.cn`),工具名抄自 `github.com/M-China/mcd-mcp-server` 的说明(2026-11-28 读的),**没有拿真实令牌试过**:打开开关之前,先用自己的麦当劳令牌接一次,看后台列出的工具名和这里写的对不对得上。
- **哪些家机能用**:清单里标了 `"tools": true` 的模型(现在是 `deepseek-flash`)。自带 Key、接了自己 Agent 的家机不用。只在一对一私聊里回复主人时用;群聊、主动找主人、到点提醒都不用。
- **和联网搜索二选一**:DeepSeek 不允许自定义工具和它自带的搜索放在同一次请求里。所以接了工具的家机,那条回复就没有联网搜索。
- **花费**:模型每回答一次(包括"我要调用某某工具"这种回答)记一次账。一条回复最多 5 次模型调用(4 轮工具 + 最后必须回答),所以最贵是平时的 5 倍,都算在这个家机当天的额度和次数里。
- **限制**:一轮最多调用 6 次工具;一次工具调用最多等 15 秒;工具返回的内容最多给模型 4000 字;每位主人每天 100 次工具调用(`chat_quota.daily_tool_calls`,后台现在没有改它的入口);每个家机最多接 3 个服务器;确认卡 15 分钟不点就过期。
- **令牌**:主人的令牌和模型 Key 一样,用 `CONNECTION_SECRET_KEY` 加密后存库,只有 API 服务器解得开,后台看不到。没有这把服务器密钥时,工具整个不可用(接口答 501)。删家机、注销账号时令牌一起删。
- **留下的记录**:哪个家机在什么时候调用了哪个工具、成没成功(`companion_private.tool_calls`);确认卡的内容和结果(`tool_requests`,跟着那条消息)。发给工具的参数和工具返回的内容,除了确认卡那一次,都不留。
- **安全上的考虑**:工具返回的内容是外面来的数据,给模型时标明"只是数据,不是指令";会改东西的操作必须主人点确认,而且服务器只执行一次;付款由主人自己在对方页面完成。但模型可能看错菜单、算错东西,确认卡上显示的是真正要发出去的参数,主人付款前在对方页面看到的才是最终的订单。
- **麦当劳的规则**:它的说明里写着令牌代表会员身份、不要分享给他人,示例只许个人非商业使用。第三方服务替用户保管令牌算不算"分享",它没有写。正式对外开放前,建议申请令牌时把《麦当劳MCP 服务规则》读一遍,或者问一下对方。
- **办没办成不确定的时候**:主人点了确认以后,如果对方没按时回答、出错,或者我们的服务器中途重启,这一单可能已经创建了,也可能没有。这种情况结果里写的是"结果不确定……请先到对方那里确认,不要直接再办一次",家机也会这样告诉主人。只有对方明确拒绝(令牌失效、限流、地址不对)时才写"没有执行"。
- **厂商不接受工具的写法时**:如果某个工具的参数说明让模型厂商报"请求不对"(400),这条回复会自动改成不带工具再写一次,主人仍然收到回复;日志里那一轮 `tools` 是 0。持续出现时,到后台把那个工具名从名单里拿掉。
- 回复日志 `chat_reply` 里:`tools` 是这一轮调用了几次工具,`asked` 表示出了一张确认卡。

## 联网搜索(默认关)

家机回答主人时可以自己上网搜,用的是 DeepSeek 接口自带的搜索工具:要不要搜由模型决定,搜索在 DeepSeek 那边完成。

- **哪些回复会带**:管理后台「模型与额度」页的功能开关"家机联网搜索"打开,并且这次是回答主人、用的是清单里标了 `"webTools": "deepseek"` 的模型(现在只有 `deepseek-flash`,DeepSeek 的文档写明这个工具只配它用)。主动找主人、提醒、日记、动态、自动记忆都不带。主人自带 Key 或自己的 Agent 的家机不受影响。
- **只做搜索,不做"打开链接"**:DeepSeek 的另一个工具会把对话里出现过的每个链接在每次回复时都重新打开一遍,又慢又费钱,所以没开。
- **花费**:搜索本身不收费,模型读到的搜索结果按输入 token 收费,所以搜过的回复比平常贵(读了多少结果就多多少,量级上是平常一条回复的几倍到十几倍;没搜的回复不变)。每条回复照常记进花费页;全平台每天的花费上限照常管着。
- **读多少结果我们限制不了**:DeepSeek 的这个工具没有"最多搜几次、最多读多少"的参数。一条回复开始前按 16,000 个输入 token 预留(账本单条的上限),结束后按实际用量结算;搜得多时实际用量会超过预留。超出的部分:按每日额度算的主人,当天剩余额度照实际用量扣;用钱包的主人最多只扣预留的那么多,**多出来的由平台承担**。所以打开开关前先用下面的命令试几次,看 `inputTokens` 一般是多少;日志里搜过的回复带 `webTokens`(这条回复实际的输入 token),常常超过 16000 就该考虑关掉或者换做法。
- **怎么看有没有在搜**:日志里每轮回复那一行(`grep chat_reply`)有 `web`:`OFF` 是这次没给模型联网;数字是搜了几次(0 是给了没用);`REFUSED` 是 DeepSeek 不接受这个工具,这条回复是不联网写出来的(这时发给模型的说明里也不会写"你可以联网")。持续出现 `REFUSED` 说明 DeepSeek 改了接口,先把开关关掉。
- **先自己试一次**(会花一点钱):`DEEPSEEK_API_KEY=... npm run chat:try -- deepseek-flash --web "今天有什么新闻"`,会打印搜了几次、用了多少 token、花了多少美分。
- 2026-11-27 写这一段时,这条路只按 DeepSeek 的文档(api-docs.deepseek.com/guides/web_tools)做了,**没有用真实的 Key 调用过**。第一次打开开关后请先发一条消息,看日志里的 `web` 不是 `REFUSED`。

## 关掉(总开关)

在管理后台(`http://companion-admin/`,见 `ADMIN_CONSOLE.md`)的「模型与额度」页点开关:全部、某一家厂商(不止一家时才有)或某一个模型。改动立刻对所有服务器生效,每次都连同原因和操作账号记进管理日志。

管理台起不来时的应急办法:用运营人员的数据库账号(属于 `companion_admin`)直接连库,执行一行,同样记日志、同样必须写原因:

```
select companion_admin.model_switch_set('ALL', '*', false, '原因');                                 -- 全部平台模型
select companion_admin.model_switch_set('PROVIDER', 'openai', false, '原因');                        -- 某一家
select companion_admin.model_switch_set('MODEL', 'deepseek/deepseek-v4-pro', false, '原因');         -- 某一个
select companion_admin.models();                                                                     -- 查看现状
```

第三个参数 `true` 是打开。

关掉后回复显示"平台模型暂时关闭",不扣额度,聊天记录照常能看。选了被关掉模型的家机,会自动改用默认模型回复;默认模型也被关掉时才显示"暂时关闭"。

名字要按清单里的写:厂商用 `providers` 里的名字(区分大小写),模型用"厂商/厂商那边的模型名"。管理台只列出清单里有的名字;直接写 SQL 时数据库不检查名字,写错了开关不会管住任何模型。两点要知道:

- 开关看的是"哪家厂商、哪个模型名"。同一个模型经由另一家转发(例如经 OpenRouter 调 Claude),要另外关那一家。
- Claude 的 Opus、Sonnet 开了"拒答时自动换模型"(`fallbacks`),换上的模型由 Anthropic 决定,不受这里的模型开关管。如果监管要求某个模型绝对不能用,把对应条目的 `fallbacks` 关掉,或者直接关掉整个厂商。

## 免费额度

每个家机每个自然日(UTC)自动有一份:默认 200 次模型调用、1 美元(占位数值)。改:

在管理台「模型与额度」页填次数、美分和原因;应急时用 SQL:

```
select companion_admin.chat_quota_set(100, 50, '原因');   -- 每天 100 次、50 美分;从新建的额度开始生效
```

用完后回复显示"今天的额度用完了"。每次调用都记在算力账本里(回复:`OWNER_DIRECT_RESPONSE`;判断要不要开口:`CHAT_TURN_DECISION`)。token 数按实际记录;费用以美分记账,调用前按上限预占(向上取整),调用后按实际用量结算(四舍五入),所以很便宜的调用不会每次都扣掉 1 美分。厂商没报用量、调用失败或服务器中途停掉的,按预占的上限扣。
