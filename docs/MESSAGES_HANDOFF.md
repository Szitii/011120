# 独立「消息」Tab｜给 Claude 的前后端对接提案

## 目标与分工

移动端拟新增独立「消息」Tab，统一查看私聊。社区通知保留自己的入口。小家仍是和家机相处的场景，从小家进入聊天时打开同一条会话，返回时回到小家。此次文档用于对齐设计，消息 Tab 和真人私信暂未上线。

前端可以先做消息列表和会话导航，接现有 `GET /v0/chats` 和会话详情，首期展示用户与自己家机的一对一会话。保留现有历史游标、发送幂等和回复轮询语义。未读徽标等服务端提供读水位后再显示。小家与消息 Tab 共用已有 `chatId`，保留各自的返回路径。

请 Claude 并行评估跨账号真人私信。现有 `/v0/chats` 是主人范围内的家机会话，请保留现行为，给真人私信独立的成员和投递规则。前端可在统一列表里接两类会话。

## 请优先定下的真人私信契约

| 范围 | 需要明确的契约 |
| --- | --- |
| 一对一会话与列表 | 成员身份、稳定的会话 ID、对端资料、最后可见消息、排序和游标。重复发起复用会话。 |
| 消息请求 | 默认如何处理陌生人、请求的发起/接受/拒绝状态和幂等行为。建议陌生人只允许附一条请求文字，接受后才开放发送。可以关闭陌生请求。 |
| 文字投递 | 服务端按当前认证账号、成员关系和请求状态验权。明确发送幂等、历史分页、内容长度、速率限制和错误码。先支持一对一文字。 |
| 未读和通知 | 读水位按成员存储，跨设备单调前进，确认未读计数和总角标来源。推送遵守可见性与隐私设置。 |
| 拉黑与举报 | 明确拉黑对请求、发送、历史与通知的影响，以及解封后如何继续。拒绝与拉黑要防重复骚扰。举报范围和证据留存由后端明确。 |

跨账号验收优先覆盖非成员无法读历史或发消息、拉黑与发送并发不会漏投、重试不会重复投递。真人私信默认不进入模型上下文。

## 后续的跨主人家机互聊

放在邀请制内测。双方主人明确授权，任一方撤回后阻止后续生成、投递和推送。先由主人触发，设每轮回复与成本上限，防止家机循环对话。模型仅接收本会话获准使用的内容和公开资料。小家日记、动作记录和主人私聊保留各自的权限边界。

请先提供真人私信的接口和状态草案，优先定成员验权、消息请求、拉黑与未读。前端并行完成现有家机会话的消息入口设计，等契约稳定后再接真人私信。
