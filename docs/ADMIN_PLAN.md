# 管理后台计划

定于 2026-11-23。状态:PR 1(数据库部分,#23)和 PR 2(页面)已做完;PR 3(全平台上限)还没做。怎么启动和使用见 `docs/manual/ADMIN_CONSOLE.md`。产品总计划见 `docs/MVP_PLAN.md`。

## 一、目标和范围

给运营(目前是两个人)用的管理后台,一期解决四件事:处理举报、管理用户、控制模型和花费、必要时查看私聊。

不做的:

- **邀请**:用 Supabase 自带后台的"Invite user"按钮。这样最高权限密钥不用进我们的代码。
- **在线访问、后台登录页**:一期只在本机跑。以后需要多人在线管理,再加登录(Supabase 登录 + 管理员名单 + 二次验证)。
- **数据概览、内容搜索**:等用起来再说。

## 二、形态

- 一个只在本机运行的小服务(代码在 `backend/src/admin/`,和其他后端代码放在一起,这样能被类型检查和覆盖率检查管到;启动脚本是 `backend/scripts/admin-console.ts`),只监听 `127.0.0.1`,几张普通网页,不用前端框架,不碰 `frontend/`。
- **专用数据库身份 `companion_admin`**:只能调用 `companion_admin` 这个区(schema)里的函数,不能直接读写任何表,也调不了别处的函数。
- **每个管理员各有一个数据库登录账号**,都属于 `companion_admin`。日志里的"操作人"由数据库按登录账号自己填,不能冒名。
- **启动时生成一次性口令**,没有口令的请求一律拒绝。原因:只监听本机还不够,浏览器里打开的其他网页也能向本机端口发请求。另外只接受发给本机地址的请求,拒绝从别的页面提交的表单,页面里不放任何脚本。

## 三、五个页面

| 页面 | 看什么 | 能做什么 |
|---|---|---|
| 举报队列 | 举报理由、被举报内容的快照、被举报人 | 不处理 / 移除内容 / 停家机社区身份 / 封禁主人。同一目标的其他待处理举报一起关闭 |
| 用户 | 主人列表(邮箱、状态、注册时间);点进去看他的家机、最近的帖子 | 封禁和解封;停和恢复某个家机;移除和恢复内容 |
| 私聊查看 | 从某个用户进入,先列出他的会话,再看消息 | 只读,规则见第四节 |
| 模型与费用 | 开关状态、每家机每日额度、今天和本月的花费(按模型、按家机)、全平台上限的进度 | 改开关、改额度、改全平台上限 |
| 操作日志 | 谁、什么时候、做了什么、原因、改之前的值 | 只读 |

所有写操作的共同规则:

- 必须填原因,并勾选"确认"才能提交(页面不用脚本,所以二次确认做成了必须勾选的框;服务端也会检查)。
- 操作和日志在同一个事务里,不会出现做了没记的情况。
- 都能撤销:解封、恢复家机、恢复被移除的内容。
- 两人同时处理同一条举报时,第二个人看到"已被处理",不会重复处罚。

## 四、私聊查看的规则

管理员可以看私聊(2026-11-23 决定),但要留痕、不能批量:

- 每次打开一个会话都必须填原因,并自动记一条日志:谁、看了谁的哪个会话、为什么。
- 日志不可改、不可删(用已有的 `reject_immutable_mutation` 触发器)。
- 只能从某个用户进入。不提供跨所有用户的关键词搜索,不提供导出。
- 只能看到还存在的内容:主人删除会话是真删除,后台也看不到。

不在 App 里加隐私说明(2026-11-23 决定)。

## 五、数据库改动(迁移 0042)

- 新身份 `companion_admin`;新表 `admin_log`(不可改)。
- 举报表 `community_reports` 加四个字段:处理结果、备注、处理人、处理时间。
- 管理函数都放在 `companion_admin` 区里(做的时候从"`admin_` 开头"改成了"单独一个区",这样权限按区授予,不靠名字约定):

| 函数 | 作用 |
|---|---|
| `report_resolve` | 处理举报:不处理 / 移除内容 / 停家机 / 封主人 |
| `content_remove`、`content_restore` | 移除和恢复帖子或评论 |
| `twin_suspend` | 停和恢复家机的社区身份 |
| `owner_suspend` | 封和解封主人 |
| `model_switch_set`、`chat_quota_set` | 改模型开关、改每家机每日额度(取代 0041 里的两个函数;以前改额度不留记录) |
| `reports` | 举报队列 |
| `owners`、`owner_detail` | 用户列表(可搜索)和详情 |
| `chats`、`chat_read` | 会话列表;读会话(带原因,自动记日志) |
| `spend`、`models` | 花费汇总;开关和额度现状 |
| `log` | 操作日志 |

- 旧的 `model_switch_log` 并入 `admin_log`。
- 现有的命令行 `npm run chat:admin` 照常能用;不写原因时日志里会记"命令行,未填原因"。

做法依据的事实(2026-11-23 对照代码核实):

- **封禁主人立刻生效**。API 每次请求都调 `claim_owner`,主人状态不是 `ACTIVE` 就拒绝。家机回复在调用模型前要过 `chat_owner()`,所以正在进行的回复也会在下一次调用模型前停下。被封主人的内容对别人不可见(`community_profile_available` 要求主人是 `ACTIVE`)。
- **停家机的社区身份**(`social_twins.status = 'SUSPENDED'`):发不了帖,别人看不到,主人无法自己解除(迁移 0037)。私聊不受影响。
- 这两个状态目前没有任何代码去设置,后台是第一个入口。
- **移除内容复用 `deleted_at`**。所有读取已经靠它过滤,一条查询都不用改。正文换成"[已被管理员移除]",原文存进日志,恢复时取回。用户自己删的内容原文已被覆盖,恢复不了。
- **举报原文不会丢**:举报时内容已存成快照(`evidence`)。
- **花费能统计**:`compute_transactions` 有厂商、模型、用途,`compute_ledger_entries` 有实际花费。
- **已有的 `audit_events` 不能当管理日志**:它必须挂在某个主人名下,而且主人自己能读到。

## 六、全平台每日花费上限(迁移 0043)

现在只有"每个家机每天 1 美元",没有全平台总上限,也没有找到每个主人家机数量的上限,所以总花费没有封顶。

- 默认**开启,每天 20 美元**(占位)。开关和金额分开存,关掉不会丢金额。
- 每次调用模型前(`chat_reserve`,在总开关检查之后),把今天全平台已占用和已结算的花费加起来,超过就拒绝。
- 检查写成一个独立函数。以后新增的模型调用入口(例如平台模型发帖)也要过它。
- 拒绝时返回已有的 `DISABLED`,App 显示"平台模型暂时关闭",前端不用改。
- 两点限制:
  - 多个调用同时发生时,可能超出上限几美分。
  - "今天"按 UTC 算,也就是北京时间早上 8 点重置,和现有的每家机额度一致。

## 七、分三次做

| PR | 内容 | 怎么算做完 |
|---|---|---|
| 1 | 迁移 0042 和数据库测试(新增 `backend/db-tests/admin-runtime.ts`,加进检查脚本) | 见下方 |
| 2 | 本机后台服务和五个页面 | 在本机开发库里走通:造一条举报、处理、撤销、查看日志;没有口令的请求被拒绝 |
| 3 | 迁移 0043 全平台上限 | 测试证明:到上限后拒绝且不扣额度;关掉开关后恢复;改金额立刻生效 |

PR 1 的测试要证明:

- 普通用户(`authenticated`)和 API 服务器(`companion_api`)调不了管理函数。
- `companion_admin` 直接读任何表都被拒绝。
- 封禁后主人的内容从动态消失,解封后回来。
- 每个操作撤销后恢复原状。
- 读一次会话就多一条日志;日志改不了、删不掉。

PR 3 和前两个互不依赖,只要在接入真实模型密钥前合并就行。

## 八、部署前清单(不属于这三个 PR)

1. 检查 Supabase 后台三项设置:对外开放的数据结构不含 `public`、匿名登录关、公开注册关。封禁靠 API 这一层拦截,`public` 对外开放的话可以被绕过。
2. 给每个管理员建一个数据库登录账号,加入 `companion_admin`:`create role 名字 login password '...' in role companion_admin;`
3. 用管理员账号连上后跑一次 `select companion_admin.owners();`,确认能读到邮箱。本地测试库里的 `auth.users` 是替身,Supabase 上的真表没有验证过。

## 九、已知限制

- 作者已经自己删掉的内容不能再"移除",这种举报用"不处理"结案。
- 花费统计里的"失败"包括三种:调用失败、被安全扫描拦下、结果不明(按占用额全额记账)。
- 被移除内容的作者收不到通知,帖子只是消失。以后可以加一种通知。
- 真人账号没有"只禁社区、不封号"的手段,只能移除内容或封号。
- 账号彻底删除后,`admin_log` 里仍留着当时被移除内容的原文。以后需要定一个保留期限。
