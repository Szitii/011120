# 双人 + 双 AI 开发协作约定（2026-11-21）

> 工作仓库：私有 `Szitii/011120`。这是建议的协作流程，不代替产品总纲。正式产品结构见 `docs/MOBILE_V2_IMPLEMENTATION_DECISIONS.md`。

## 1. 唯一共享代码与决策入口

- GitHub **同一个私有仓库**是团队唯一共享代码源；两台电脑各自的本地修改不会自动同步。
- `main` 为集成基线：双方**不直接在 main 写功能**。
- 每个任务单独建分支：`feat/模块-内容`、`fix/问题`、`docs/内容`。
- 完成一个任务：本地检查 → commit → push → GitHub Pull Request（PR）→ 另一位查看变更和测试结果 → merge → 双方更新本地代码。
- GPT 与 Claude 是协助审查／编程的工具，不应各自在独立副本中长期实现同一功能后直接互相覆盖。

## 2. 当前必须特别注意的两个分支

- 用户 Mac 的本地 `fix/expo-sdk58` 已有 `d16d6d2` 提交（Expo 58 iPhone 已经能打开）。**尚未推送**，需要在该分支执行 `git push -u origin fix/expo-sdk58`。这是后续 iPhone 预览使用的依赖基线。

- Gemini/Claude 提出的产品建议在人工决策前只是建议，不得直接改写已确认产品原则。

## 3. 任务分工建议

- 移动端 UI / 导航 / 用户体验：优先由一位负责人和其 AI 负责，减少同文件冲突。
- 后端 API / 数据库 / 社交权限与 Provider：优先由另一位负责人和其 AI 负责。
- 需要改变前后端接口时，先在 GitHub issue/PR 描述要增加的字段、端点、权限和测试验收，再由双方并行实现。
- 若两位都想做前端，切分不同页面/目录，避免同时编辑 `apps/mobile/App.tsx`。
- 每次合并之前，至少确认：没有串号/权限泄露、数据确实来自 API 或明确的静态预览、原功能没有回归、TypeScript 和相关测试通过。

## 4. PR 内容模板

**做什么**：一句话描述功能和对应产品需求。

**修改范围**：主要文件及 API 契约（如果有）。

**怎么验证**：执行命令、实际设备截图/录屏、已通过和未通过的检查。

**已知限制**：未接通的 API/数据、模拟和真实功能的分界。

**需要对方确认**：产品与技术取舍、可能的文件冲突、上线风险。

## 5. 安全与隐私

- 项目保持 private，朋友使用自己 GitHub 账号的协作者权限；不要共用私人令牌或在聊天中贴密钥。
- 不提交 .env、Token、用户聊天记录、敏感记忆和 API key。
- 用户明确授权前，不执行生产数据删除、真实消费、外部账号操作或对 main 的破坏性重置。
