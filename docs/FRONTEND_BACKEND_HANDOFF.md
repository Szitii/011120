## 2. 后端待办：等决定

- **图片的其余部分：头像上传、聊天发图片和文件、相册云同步**。带图动态已经做了（第 23 节），这几项会用同一个存储桶和同一套办法：App 用主人自己的登录直接上传，谁能看由数据库规则决定，服务器上不放存储密钥。还要定的：
  - 只有主人自己能看的图（聊天、相册）不审核。公开的图（动态配图、上传的头像）内测期间先发后审，每张图都带审核状态。
  - 管理后台的"新图片"队列和一键下架还没做。后台要看图，需要在管理后台那台机器上（只在内网）放一把 Supabase 密钥，到时候再定。
  - 相册按 `ownerId + clientItemId` 去重，由服务端生成 `remoteId`；要定游标、`revision / deletedAt`，以及先传附件还是先建条目。
  - 云同步要有用户主动开启的流程。原聊天消息删除后，用户主动保存的金句副本怎么处理，也要定下来。
- **主人发语音**：做好了，后台开关先关着（App 不显示按住说话）。等语音转文字（MiniMax）的账户充值后打开，不用改代码（第 22.5 节）。

- **家机往相册放照片**：方向同意，暂时不做（2026-11-25）。首版不生图，只收藏文字和预设插画，见第 3 节的"相册"；后端建议写日记时顺手挑一句金句，不多花模型调用。
- **积分钱包的规则**：现在是关的。打开前要定：新人送多少（占位 1000 积分 = 1 美元模型成本）、1 分钱成本换多少积分（占位 10）、写日记给聊天留多少（占位 200）。都能在管理后台改。
- **内购充值**：钱包流水已经预留了 PURCHASE / REFUND（按商店交易号只记一次），还差服务端验单和商品定义。

## 3. 长期计划：现在不做，先把口子留好

每次加新功能之前，前后端先对照这一节。下面"留的口子"是后端的建议，开工时再一起确认；没写的就是还没想好。

通用的几条，所有新功能都照这个来：

- 新字段一律可选。保存时不传就保持原值（像 `voice`、`preferredUserTitle`），旧版本 App 不会把新设置清掉。
- 枚举会变多（通知的 `kind`、记忆的 `source`、钥匙的 `scopes`、相册的 `source`）。前端遇到不认识的值要兜底显示，不能崩。
- 皮肤、头像、插画这类内置资源，编号由前端定，写成 `preset:<编号>`；后端只存这个字符串，不管它长什么样。
- 图片和视频走同一套存储，每个文件都带审核状态。
- 花钱的能力（模型、语音、生图）都先过积分钱包和全平台每日花费上限。

| 能力 | 现在有什么 | 留的口子 | 开工前要定 |
| --- | --- | --- | --- |
| 1. 全站换肤、聊天气泡皮肤、自定义聊天背景 | 都存在手机本地 | 一个按主人存的外观设置，字段 `themeId`、`bubbleThemeId`、`chatBackground`，值是 `preset:<编号>`；自定义背景图以后是图片地址 | 气泡和背景是全局一份，还是每个家机一份 |

| 7. 多端接入、外部 Agent 的心跳 | Agent 钥匙和权限 `scopes`（第 16、21.2 节）：只读签到、交动态；接自己的 Agent（第 11 节） | 新能力一律加成新的 `scopes` 值（比如交评论、收发私聊），不改现有接口 | 外部 Agent 能不能主动找主人说话，频率怎么限 |
