# 给后端 Claude 的接口与协作交接清单

本轮前端从 `e8fbc39` 开发。接口以已发布的 `contracts/` 为准。本轮前端使用现有会话、动作、通知和日记接口，纪念日与相册先存设备。下表的新增接口和字段是对齐提案，请后端确认契约后再接入。

## 1. 四 Tab 与消息通知

| 项目 | 内容 |
| --- | --- |
| 要新增的功能 | 「消息」Tab 管理现有一对一家机会话、同一主人名下家机群聊，以及社区通知和主人通知。通知点击后进入对应内容，返回原通知列表。 |
| 前端本轮 | 用 `GET /v0/chats` 和既有会话详情、发送接口。社区通知按当前 actor 调 `GET /v0/community/notifications` 和对应的 `PUT …/{notificationId}/read`，主人通知用 `GET /v0/life-event-inbox` 和对应的 `PUT …/{itemId}/read`。分别处理分页与已读。小家继续发送既有动作接口，聊天详情负责回复轮询。 |
| 需要后端 | 先确认会话读水位契约，建议每个成员保存单调递增的最后已读序号以及服务端未读数，支持跨设备恢复。通知若需统一角标，按可见范围返回汇总。主人通知补充可导航的目标类型与 ID，目前前端从它进入生活记录。 |
| 以后新增真人私信 | 另定成员授权、陌生人请求、拉黑、举报、分页、发送幂等与投递错误。真人内容默认不纳入家机模型上下文。跨主人家机互聊后续另定双方授权、撤回和生成预算。 |

## 2. 小家纪念日和日记

| 项目 | 内容 |
| --- | --- |
| 要新增的功能 | 用户设定相伴起始日，房间下方显示自然日计数。茶几和下半屏日记卡打开同一份日记。 |
| 前端本轮 | 纪念日按 Owner 与当前家机存 `startDate: YYYY-MM-DD`、`timeZone`，允许早于注册的历史日期。日记继续复用 `GET/POST /v0/companions/{id}/diary`、删除条目与 `/diary-settings`。双入口共用同一路由。 |
| 需要后端 | 纪念日跨设备后，请提供按归属关系读取、保存、清除日期的契约，确认 `ownerId / companionId / startDate / timeZone / revision` 和版本冲突语义。日记继续沿用现有契约，联调环境请确认模型与迁移就绪。 |

## 3. 统一相册与文件同步

| 项目 | 内容 |
| --- | --- |
| 要新增的功能 | 统一保存小家实时拍立得、本机照片、聊天金句；票根与黑胶时刻在有真实事件来源后接入。 |
| 前端本轮 | 按 Owner 和家机分区。索引持久化本地 ID、类型、时间和内容，图片保存在私有文件目录（Web 使用 IndexedDB）。金句只保存用户主动选的一条。每条预留 `remoteId: null`、`syncStatus: "local_only"`，本轮不上传。 |
| 需要后端 | 对齐相册列表、创建、删除和附件上传。建议使用 Owner-scoped 私有对象存储，上传签名限制类型、大小和目标路径，读图按条目鉴权。按 `ownerId + clientItemId` 去重，服务端生成 `remoteId`。确认游标、`revision / deletedAt`、文件大小/MIME/哈希、附件上传与条目提交的顺序。 |
| 需要共同定稿 | 云同步须有用户开启流程。明确原聊天消息删除后，用户主动保存的金句副本如何处理；若扩展到跨账号私信，重新核对授权、举报和删除语义。 |

## 4. 全站皮肤、创作者投稿与商城

| 项目 | 内容 |
| --- | --- |
| 要新增的功能 | 「我的 → 装扮」管理界面主题、房间搭配和人物外观。创作者后续可投稿皮肤、摆件和宿主支持的小组件，审核后发布或售卖。 |
| 前端以后怎么做 | 使用同结构的内置和远端 Manifest，记录 `schemaVersion / packId / version / minAppVersion / layoutId` 与槽位资源表。先验证 10 个换肤槽与人物动作，再接文件分批下载、完整校验和内置回退。组件用声明式参数映射到现有原生组件。 |
| 需要后端 | 目录及穿戴状态、不可变发布版本、资源哈希与临时下载授权。投稿需暂存上传、版权声明、版本审核、发布、举报及下架。依资产所有权、已购权益和审核状态控制读取和下载。 |
| 交易权益 | 确认 App Store / Google Play 商品与 `packId` 映射。服务端验证购买凭证和账号归属，幂等发放权益，提供权益列表、恢复购买、退款和撤销。明确停止新购与安全撤销的区别，以及离线穿戴的可用期限。 |

## 联调优先顺序

1. 先用现有会话、两类通知、动作及日记接口联调，确认角色切换时的访问边界。
2. 冻结聊天读水位、通知目标和关系日期契约。
3. 对齐可选的私有相册同步、文件上传与删除。
4. 免费皮肤目录与穿戴稳定后，再安排创作者审核和付费权益。
