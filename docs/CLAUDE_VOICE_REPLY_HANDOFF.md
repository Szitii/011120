# 给 Claude 的语音回复联调与社区接口复核

审查基线为 GitHub `main@b7b4760`。这份清单请后端复核和执行。前端第一批复用现有聊天设置 GET/PUT，拆开试听与选音色，统一使用一个保存入口，并按服务端回执显示实际保存状态。

## P0 · 确认「林屿」为何只回文字

同名家机有两位，请按失败当轮的 `chatId` 确认成员的 `companionId`。核对该家机的 `GET /v0/companions/{id}/chat-settings` 实际保存的 `voice` / `revision`，以及同环境 `GET /v0/voices` 是否仍含该音色。试听使用独立接口和缓存，单独试听成功只能验证试听。用户用文字请求语音，复现也用简短的测试文字即可。

- 按 `replyId` 追踪模型渠道、是否产出语音标记、合成和消息落库，再确认聊天返回的消息是否有 `audio`。没有原始追踪时，把原事故记为未定因，用测试账号复现即可。前端有 `audio` 才显示播放入口。
- 在共用流程记每轮一条结构化结果，至少区分无可用音色、无标记、超长、额度用完、额度查询失败、安全扫描改写、TTS 失败或超时、已合成但未成功写入、已写入。追踪 ID、渠道、耗时和安全的状态码已够定位。日志里排除正文、私人记忆、密钥、音频及供应商原始报错或响应体。
- 核对线上部署版本和迁移 `0058`。当前语音费用的记账错误可被容错，分别验证音频产出与费用入账。若线上已修或已有日志，以线上追踪结果为准。

源码见 [聊天路由](../backend/src/chat/http.ts#L249)、[回复与音频写入](../backend/src/chat/replies.ts#L127)、[语音降级逻辑](../backend/src/chat/replies.ts#L229)、[音色与试听](../backend/src/chat/voices.ts#L131)、[费用迁移](../backend/supabase/migrations/202611250058_costs.sql)。

## P0 · 主人明确想听时优先语音

平台托管、BYOK 和自建 Agent 共用语音标记解析及 TTS。现有提示词介绍了语音标记，普通回复以打字为主。建议先在共用提示词补一条规则：平时家机自主选择，主人明确希望听语音时，优先把第一条简短、合规的回复标注为语音。沿用已有安全扫描、每条 120 字、额度和 25 秒合成超时；合成不可用时保持现有文字降级。

若真机验证提示词仍不够可靠，尤其自建 Agent 忽略指令，再与前端商定一次性的「请用语音回复」字段，由服务端对同一次生成的首条合规短句尝试合成。无需新增端点、关键词表或额外模型调用。用户提示只在服务端确认本轮请求过语音且发生降级时展示；普通消息继续沿用现有响应。请先对齐字段及旧客户端兼容，再更新契约。

验收覆盖三个渠道、无音色、明确要语音、普通文字、额度耗尽、超时与安全降级，并核对同名家机及跨账号隔离。源码见 [语音提示词](../backend/src/chat/prompt.ts#L16)、[连接模型](../backend/src/connections/model.ts#L134)、[共用回复](../backend/src/chat/replies.ts#L247)。

## P0 · 社区接口复核与通知放量

- 请求指纹目前只包含身份、动作、目标和正文。同一幂等键改 `mentions` 会重放旧提及。数据库已校验可见范围冲突，并在重放时序列化当前记录。请将规范化后的提及纳入幂等校验并兼容历史键。验收同键同内容无重复帖子或通知、同键不同提及冲突，以及私密或仅关注者可见的帖子重试保持原权限。
- 前端会先接入 `LIKE`、`MENTION` 及未知类型兜底，再与后端协同打开 `COMMUNITY_NEW_NOTICES`。现有老版本会把新增类型显示成评论，请把客户端版本纳入放量安排。

源码见 [HTTP 请求指纹](../backend/src/community/http.ts#L212)、[发布和重放](../backend/supabase/migrations/202611250056_post_visibility_mentions.sql#L241)、[通知开关](../backend/supabase/migrations/202611250056_post_visibility_mentions.sql#L222)。
